## 1. Training hall (gym, 16 skills)

### 1.1 Which values count
`InitShowedList` (嚱.cs:108-151): for each ability id the user owns, **only the row whose Level == the user's level** is added (`userAbilityValues.AddValues(row.Values)`, line 128). Lower levels are **not** summed, so the server's `v` for level N must hold the **cumulative** value. Level 0 means the id is absent from `u`, so it contributes 0. The cache is cleared on every rebuild (load, buy). UI sort: ids 2 and 1 are swapped, so Здоровяк shows first (line 115).

`嚲.NormalizeValues` (嚲.cs:139-170):
- id 7 (Барахольщик): `v` is **ignored** and replaced by `[{"t":"2","wam":"min(50, L*10)"}]`, i.e. +10/20/30/40/50 %.
- `v` that starts with `[` or `{` is used as is.
- otherwise a plain integer `v` becomes `[{"t":"1","<legacy>":"N"}]` (Point), with legacy key from `GetLegacyStatName` (嚲.cs:172-211).
`嚲.Description` overrides the localized text for ids 7/12/13/16 (嚲.cs:50-76): 7 → `+min(50,L*10)% боеприпасов`; 12 → `+min(25,L*5)% урона когтями Зараженного`; 13 → `+min(20,L*4)% здоровья за Зараженных`; 16 → `-min(25,L*5)% урона от Зараженных`.

### 2.3 Movement speed — CLIENT applied (two separate paths)
**(a) Real local movement** (SoldierController.cs:366-401, called from OnEnable / Reset and from `RefreshBattleMovementValues` at PlayerManager.cs:5893):
```
runner = 1 + clamp(嚱.GetRawValue(CharacterSpeed), 0, 10) * 0.01f      // gym raw sum, Point/Percent ignored
wear   = max(0.01f, 1 + PlayerManager.GetLocalWearMovementSpeedPercent() * 0.01f)   // = GetLocalWearStatTotal("speed_percent") incl. set bonus (PlayerManager.cs:3008)

runSpeed=15.5k  runStrafe=13.5k  walk=7k  walkStrafe=6.5k  crouchRun=5.5k  crouchRunStrafe=5k  crouchWalk=3.5k  crouchWalkStrafe=3.2k
```
Per frame (SoldierController.cs:478-531), maxForward is chosen from walk/crouch. For humans: back = forward and side = the strafe value, then all three × `ShotController.GetSpeedMultiplier()` (ShotController.cs:3108-3125: `max(1, weapon.SpeedValue)`, ×1.25 if ONE_HANDED_COLD_ARMS or the weapon has attribute "R"; `SpeedValue = 1 + [79][78]/100`, the configured workshop speed, 噔.cs:544-549). If the check fails, it calls `SendEnterBaseRequest(5)` (anti-cheat). For zombies (team 1 in ZOMBIE mode): forward/back fixed at 26 (11 while walking), strafe = the strafe value above, ×0.5 during hit stagger.
`PlayerManager.SpawnMe` (5874-5889) first sets 16.12×(1+cspd%) / 14.04×, but RefreshBattleMovementValues overwrites this at once. 16.12 = 15.5×1.04.
**The wear flat `BattleSpeedBonus` and wear `v` `cspd` entries are NOT used for local movement.** Only `speed_percent` (item + set) is used.

**(b) Actor-data speed `[96][95]`** (sent; remote players use `Speed = [95]/10` for WalkController.setSpeed at CombatPlayer.cs:671/893):
```

b = ApplyLocalWearBattleBonus(CharacterSpeed, b)             // 3376 (flat BattleSpeedBonus + v Points + Convert.ToInt32(b*(vPercent+speed_percent)*0.01f))
if max workshop speed % over weapons ([118]) > 0:            // ApplyLocalUserEquipmentToActorData 1375-1391

```
The gym cspd is not folded into [95]; it is sent separately in [103].

### 2.4 Ammo (Барахольщик) — CLIENT applied
`ResolveLocalBattleTotalAmmo` (PlayerManager.cs:2347-2412): after the per-weapon base `total` is resolved:

### 2.5 Fire rate (Шустряк) — CLIENT applied

### 3.2 `ApplyLocalWearBattleBonus(t, b)` (PlayerManager.cs:2891-2944)
Equipped list = `GetLocalEquippedWearsForBattle` (3202-3220). Slot order: Hats, Masks, Gloves, Shirts, Pants, Boots, Backpacks, Others, Heads. Each item is resolved by id from `嗭.Instance.Wears` (1648-1665), and duplicates with the same WearID are dropped.
```
flat = Σ_items Direct(t)          // Health→BattleHealthBonus, Defense→BattleDefenseBonus, Speed→BattleSpeedBonus, else 0 (3183-3200)
     + Σ_items Σ_{v entries with ValueType==t, Point} Value
pct  = Σ_items Σ_{v entries with ValueType==t, Percent} Value
     + (t==Health ? GetLocalWearHealthPercentTotal() : t==Speed ? GetLocalWearStatTotal("speed_percent") : 0)
return b + flat + (pct!=0 ? Convert.ToInt32((float)b * (pct*0.01f)) : 0)    // percent of the base b only; round half to even
```
If an item's `v` fails to parse, that item's v is skipped (try/catch), but its flat value is still counted.
`GetLocalWearHealthPercentTotal` (2946-2966): Σ per item `health_percent` (if 0 then `cheal_percent`), plus the set bonus for complete sets (same rule as below).
`GetLocalWearStatTotal(key)` (2982-3006): Σ per item `battleStats[key]`. For each distinct set key, the **first** item in slot order whose set is complete adds `GetLocalSetBonusStat(item,key)` **once**.

### 3.3 Sets
- **Set key** (`GetWearSetKey` 3102-3128) = `BattleSetId` if non-empty, otherwise the sorted `set_items` joined with "," (no `set_items` → no set).
- **Complete** (`IsLocalWearSetComplete` 3078-3100): **every** id in *that item's own* `set_items` is among the equipped WearIDs. An item with empty `set_items` is never complete (even when it has set_id). The item itself does not need to be listed.
- **Set-bonus value** (`GetLocalSetBonusStat` 3051-3076): scan the equipped items with the same set key in slot order and take the first non-zero `set_bonus[key]`. Per stat key, so different keys may come from different items.
- **Carrier for transfer** (`IsLocalSetBonusCarrier` 3027-3049): the item's set must be complete. The carrier is the equipped item with the **smallest WearID** among same-key items that have `HasBattleSetBonus`. Only that item's transfer hashtable gets `+GetLocalSetBonusStat`.

## 6. Summary: client-applied vs server-only
- **Client-applied (local player):** max HP (gym 2 + wear flat/v/health% + set + Живчик + hoodAdmin), max armor (gym 1 + wear flat/v), movement speed (gym 3 raw% × wear speed_percent incl. set × weapon SpeedValue), reserve ammo (gym 7), fire interval (gym 5), deviation (gym 10), fall −50% (e3, offline/Photon only), explosion radius (150/151), exp (10/156).
- **Transferred only (server computes):** gym cdecdam, wcrit, wmdam, wmxdam, whcrit, zzdam, zzheal, zzdecdam, zhdam, zhdecdam (and cspd/wrap/wam/wacc again); wear keys 97..72 above (jump, all defence %, damage_bonus %, damage-def %); speed [95] for remote animation; enhancer list [108]; base_max_health/energy; wear_ids/weapon_ids.
- **Parsed but unused:** shotgun jump bonus keys (dead `GetLocalShotgunJumpBonusPercent`), 嗲 WeaponAngle/WeaponReload/Kamikaze/Medication.

## 7. Ambiguities / open points
1. Gym values per level come from the server `v` (not in the dumps). Only the current level's row is applied, so `v` must be cumulative. Plain-number `v` is treated as Point.
2. Шмотник: loc says +10/20/40/60/80, but the normalizer maps a raw 10/20/30/40/50 to 16/32/48/64/80 (other values are clamped ≤80). So the server's raw values may be 10..50, which would make the L1 tooltip "+10" vs actual 16 inconsistent.
3. Барахольщик: loc 10/30/40/50/60 % vs forced 10/20/30/40/50 % (client wins).
4. Мутант: Живучий: loc says HP points but the client override and the clamp 0..20 imply a percent. Server only either way.
5. Живчик: the client uses 2% of training HP (not of the wear-boosted HP); the description says 5%.
6. Wear flat speed (`BattleSpeedBonus`, v `cspd`) affects only actor-data [95], not real movement. Gym speed uses GetRawValue (Point/Percent ignored), clamped to 10.
7. Actor-data speed: b = LocalPlayer.Speed×10, where Speed comes from the server's join data. If the server echoes a [95] that already holds the wear bonus, the client adds the wear bonus again (possible double counting); integer /10 also truncates.
8. Light Landing on the HTTP server is not applied by the client; the raw 40/80 is sent.
9. Set completeness uses each item's own `set_items`, so inconsistent data between set pieces gives an order-dependent result. The carrier is the min WearID with non-empty set_bonus, but local totals take the first slot-order item. Same totals, different attribution.
