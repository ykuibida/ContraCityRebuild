## Most important differences (fix first)

1. **The crouch eye height never reaches 4.7 in ours.** P/NE set `FPSCamera.Walk` from PlayerLocal.ReadKeyboardInput: true only while a bound WASD movement key is held (P `PlayerLocal.cs:141-182`, NE `PlayerLocal.cs:121-187`). Crouch comes from `SetCrouch` (P `PlayerLocal.cs:275`). Ours sets `fpsCamera.Walk = soldier.walk` (`SoldierController.cs:94`). That `walk` is also true when idle and always true when crouching (`:132`). Result in ours: crouching always targets CroachWalkHeight 5.2. Originals: crouch and still = 4.7, crouch and moving key = 5.2.
2. **The BoxCollider = flat-ground quirk is invented in practice** (`CharacterMotor.cs:204`, `hit.collider is BoxCollider ? up : normal`). Originals write `hit.collider.GetType() != Type.GetType("BoxCollider")` (P `CharacterMotor.cs:663`; NE `CharacterMotor.cs:1012`, the same logic inverted). `Type.GetType("BoxCollider")` returns **null**: the name is unqualified, UnityEngine.BoxCollider lives in UnityEngine.dll, and Assembly-CSharp has no global BoxCollider. So the originals **always use hit.normal**. In ours, touching any box-collider wall while moving down counts as ground with normal up. That can give wall "grounding", re-jumps off walls and wrong slope handling on rotated-box ramps.
3. **The eye camera position is wrong in ours.** PREFAB MainCamera (FPSCamera) local position is **(0.0084, 6.268, 0.6457)**, a child of the root (PREFAB ~308316). Ours is (0, 6.5, 0) (`PlayerRig.cs:25,30`). The forward offset of 0.65 is missing. The originals also start at y 6.268 with `moving=false`, so the eye stays at 6.268 until the first Walk or Croach change.
4. **Eye-height snap.** In P/NE, when the lerp gets within `error` (0.05), the snapped value is **not written** (P `FPSCamera.cs:279-287`; NE `FPSCamera.cs:312-317` has an explicit `return`). The camera therefore rests 0.05 to about 0.1 short of the target. Ours writes the exact target (`FPSCamera.cs:45-46`). This is a small visual difference, but it is not a port.
5. **FOV.** Ours defaults to 74.66 (`TRInput.cs:86`, labelled as the user's own registry value), with option range 40–95, applied once at spawn (`PlayerRig.cs:33`). In Penta the serialized MainCamera FOV is **50** (PREFAB 308329). It becomes 55×zoom only after a sniper zoom/unzoom (P `FPSCamera.cs:324`), **90** when infected as a zombie and **60** when cured (P `CombatPlayer.cs:859-860, 893-894`). Penta has no FOV option. NE has a rebuilder FOV option ("Угол обзора (FOV)" at `OptionPopup.cs:976`) with default **55** (`喞.cs:30, 888`), range 40–95, ×1.5 for zombies clamped to 110 (`FPSCamera.cs:341-344`), re-applied every LateUpdate. Ours matches neither default and has no zombie FOV.
6. **Mouse sensitivity default.** Ours is 1.02, so MouseSensityX = 51 (`TRInput.cs:83-84`). P and NE: field `sensivity = 3`, so 150 (P `OptionsManager.cs:380, 222`; NE `喞.cs:55, 339`). On the very first launch (no "use" pref) the static default **230** is left in place until the options slider is drawn or the next launch (P `OptionsManager.cs:32, 55-62`; NE `喞.cs:65, 84-94`). Ours is not a client default.
7. **Invert Y in first person is not Penta.** P SoldierCamera never reads InvertMouseY (`SoldierCamera.cs:417-471`); invert only affects TPS (`MouseOverLook.cs:169`). NE applies it in all three FPS modes (`SoldierCamera.cs:340/352/364`), probably a rebuilder change. Ours follows NE (`SoldierCamera.cs:48`).
8. **Aim sensitivity blending is NE-only, and our blend is different.** Penta has none: `speed`/`aimSpeed` are computed but unused (`P SoldierCamera.cs:422, 433`). NE (rebuilder: "Чувствительность прицела" `OptionPopup.cs:330`, pref `cmaimsensity`) uses an exponential `Lerp(blend, target, dt*15)` and also blends while the sniper is zoomed (`NE SoldierCamera.cs:393-401`). Ours uses a linear `MoveTowards(…,15*dt)` and aim only (`SoldierCamera.cs:35`). The final value formula is equivalent.
9. **Dead player.** P/NE motor `UpdateFunction` **returns immediately** while the local player is dead: no gravity, no movement (P `CharacterMotor.cs:271`, NE `:268`). Ours keeps simulating with `canControl=false` (`SoldierController.cs:61`, motor unchanged).
10. **Fall damage and KillY are not Penta.** Penta has no client fall damage or kill height; it only plays the "FallDown" sound after 1.7 s in the air (P `SoldierController.cs:334-338`). NE fall damage is a rebuilder addition: `[FallDamage]` logs, `BattleServerHttpClient.RequestEnvironmentDamage(a,"fall")` (`CharacterMotor.cs:640-714`). Ours ports the NE thresholds but changes the inputs. It tracks with `cc.isGrounded`, not the motor's `grounded`. It measures max fall speed from the position delta, not `-movement.velocity.y` (NE `:627`). It runs `TakeDamage`, which applies `DamageTakenReduction` (NE `ApplyDamageArmorFirstAndReport` `PlayerManager.cs:8467` does not). It has no zombie exclusion (NE `:687`). `KillY` (`PlayerVitals.cs:111-116`) exists in **neither** client and is invented. The 1.7 s FallDownEffect sound is **missing** in ours (only a counter, `SoldierController.cs:97`).
11. **Menu pause.** P/NE `SoldierController.Update` returns when `GameHUD.IsShowMenu`, freezing input; the motor keeps its last `inputMoveDirection` (P `:238-241`). Ours has no menu gate. Ours instead gates mouse look on `Cursor.lockState` (`SoldierCamera.cs:34`); that gate is not in P or NE SoldierCamera, so it is an extra.
12. **Taunt (TPS) camera.** The PREFAB TPSCamera FOV is 60 (308208). Ours copies the FPS camera, so it uses the option FOV (`FighterBody.cs:57`). The Penta TPS camera has a MouseOverLook orbit: sensitivity 500, pitch ±60 (min/maxY ±30 ×2), scroll/PageUp/PageDown zoom, invert honoured (P `MouseOverLook.cs:72-160`; PREFAB 308272-308285). Ours has a fixed camera at (0,0,-10) with no mouse orbit, so this is missing.
